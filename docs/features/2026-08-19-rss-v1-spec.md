# RSS 阅读 V1 需求规格

## 1. 背景与目标

当前桌面应用已提供书签、笔记和 Todo。本期新增独立 RSS 工作区，完成“发现或添加订阅、刷新文章、浏览全部/未读/单 Feed 列表、阅读 Feed 正文、维护已读状态”的本地闭环。

RSS V1 仅供当前桌面应用本机使用，数据写入现有 SQLite 数据库。它不接入云同步、本地 HTTP API 或 Chrome 扩展，不提前实现收藏到书签、Readability、OPML、搜索和后台调度。

## 2. 已确认的产品范围

### 2.1 全局导航

- 主导航新增 `RSS` Tab，位于 Todo 之后。
- `Cmd/Ctrl+4` 打开 RSS 工作区。
- RSS 页面内部暂不增加快捷键。

### 2.2 固定三栏布局

RSS 页面固定为：

```text
Feed 侧栏 | 文章列表 | 文章正文
```

- Feed 侧栏复用现有 `CollapsibleSidebar`，展开宽度固定，折叠后保留窄栏入口。
- 文章列表和正文栏使用固定宽度策略，V1 不提供拖拽调整。
- 初次进入默认选择“全部文章”，但不自动打开第一篇文章，避免意外标记已读。
- 没有 Feed、没有文章、没有未读文章和没有选中文章时分别展示明确空状态。

## 3. Feed 侧栏与状态

侧栏固定入口为：

1. 全部文章；
2. 未读文章；
3. 所有订阅 Feed。

规则：

- “全部文章”“未读文章”和每个 Feed 均显示未读数，超过 999 显示 `999+`。
- 不增加“刷新失败”分类；失败仅通过 Feed 行 icon 表达。
- Feed 行 hover 时显示刷新、编辑和删除操作。
- 编辑仅允许修改本地显示名称，不允许修改 Feed URL。
- 刷新失败 icon 展示最近错误与失败时间；下一次成功刷新后消失。
- 已读和未读文章的排序权重相同，只通过 icon、字重和文字颜色区分。

## 4. 添加与发现订阅

### 4.1 输入范围

支持：

- 直接 RSS 2.0 URL；
- 直接 Atom URL；
- 声明了 `<link rel="alternate">` 的普通网页 URL。

不支持页面链接扫描、常见路径猜测、RSSHub、JSON Feed 和需要认证的私有 Feed。

### 4.2 单弹窗流程

```text
输入 URL → 安全请求 → 解析或发现 Feed → 选择结果 → 预览 → 修改显示名称 → 确认订阅
```

- 只发现一个 Feed 时直接展示预览。
- 发现多个 Feed 时在同一个弹窗内显示带标题和 URL 的单选列表。
- 切换选择后，下方异步更新该 Feed 的标题、站点地址和最近文章预览。
- 未发现 Feed 时显示明确错误并保留输入。
- 抓取和解析成功前不能确认订阅。
- 确认后在同一事务中保存 Feed 与首批文章；失败不得留下半成品数据。

### 4.3 标题与重复订阅

- 分别保存 Feed 原始标题和用户自定义标题，界面显示 `custom_title ?? title`。
- 后续刷新可以更新原始标题，但不能覆盖自定义标题。
- 重复判断同时考虑规范化输入 URL、最终重定向 URL、已存 `source_url` 和 `feed_url`。
- 发现重复时阻止添加，并在侧栏定位已有 Feed。
- 永久重定向后更新实际使用的 `feed_url`，但保留首次输入的 `source_url`。

## 5. 刷新策略

### 5.1 自动与手动刷新

- 每次进入 RSS 页面时，逐 Feed 检查最后成功刷新时间。
- 只刷新从未成功或最后成功时间超过 15 分钟的 Feed。
- 最近失败不延长新鲜期。
- 页面顶部提供“刷新全部”，Feed 行提供“刷新此订阅”。

### 5.2 并发与反馈

- 刷新全部最多并发 4 个 Feed。
- 同一个 Feed 同时最多一个刷新任务；重复触发复用进行中的任务。
- 单个 Feed 失败不取消其他任务。
- V1 不自动重试。
- 刷新全部结束后显示一次汇总 Toast，例如“刷新 12 个订阅，新增 28 篇，2 个失败”。
- 分别保存最后成功时间、最近失败时间和最近错误。

## 6. 网络与安全边界

所有 Feed 和网页发现请求必须：

- 只允许 HTTP/HTTPS；
- 拒绝 localhost、私有网络、链路本地、组播、未指定地址等目标；
- DNS 解析后的全部地址都必须为公共地址；
- 每一次重定向都重新解析并校验目标，防止 DNS/重定向绕过；
- 总超时 15 秒；
- 最多跟随 5 次重定向；
- 流式读取响应，解压后的响应体上限 5 MB；
- 不启动 Headless Chrome，不绕过 403。

错误对用户使用稳定、友好的错误码与消息；底层日志保留 URL、HTTP 状态和错误上下文，但不记录完整 Feed 正文。

## 7. RSS/Atom 统一模型与文章身份

Rust 后端将 RSS 与 Atom 条目转换为统一 Entry：

- RSS 正文优先 `content:encoded`，其次 `description`；
- Atom 正文优先 `content`，其次 `summary`；
- Atom 链接优先 `rel=alternate`；
- 解析作者、发布时间、GUID、链接、正文和摘要；
- 相对链接和图片地址使用文章 URL，缺失时使用 Feed/站点 URL 解析；
- 缺失发布时间时保留 `published_at = NULL`，列表使用抓取时间兜底。

去重键优先级：

1. GUID；
2. 规范化后的文章链接；
3. 标题与发布时间生成的稳定 SHA-256 哈希。

同一 `(feed_id, dedupe_key)` 再次出现时，更新远程字段但保留本地 `is_read`。

## 8. HTML 清洗与摘要

- HTML 在 Rust 写入数据库前完成相对 URL 重写和清洗，数据库只保存安全 HTML。
- 使用成熟清洗库的 allowlist，不自行实现字符串替换型 sanitizer。
- 删除脚本、iframe、object、embed、表单、内联事件、危险 style 和非 HTTP/HTTPS URL。
- 正文链接统一由系统浏览器打开，不在阅读栏内部导航。
- 允许 HTTPS 图片，增加懒加载和响应式尺寸；移除不安全图片地址。
- 摘要优先使用 Feed summary；缺失时从清洗正文提取纯文本、合并空白并截取约 140 个字符。

## 9. 文章列表与阅读

### 9.1 查询范围

- 全部 Feed 的全部文章；
- 全部 Feed 的未读文章；
- 单个 Feed 的全部文章。

不增加单个 Feed 内的二级“全部/未读”切换。

### 9.2 列表与分页

- 每项展示未读圆点、标题、Feed 名称、发布时间和摘要，不显示缩略图。
- 无限滚动，每批 30 篇。
- 使用时间与 id 组成的游标分页。
- 稳定排序为 `COALESCE(published_at, fetched_at) DESC, id DESC`。
- 游标绑定查询范围，错误范围的游标不得用于另一个 Feed 或未读模式。

### 9.3 已读行为

- 点击文章并切换到正文后立即标记已读，不等待远程图片。
- 支持手动改回未读，不支持批量标记已读。
- 在“未读文章”视图中，刚读文章保留在当前已加载列表并更新样式；重新查询后才消失。
- 未读标题加粗并显示圆点；已读使用普通字重和较弱文字颜色；选中状态使用独立背景色。

### 9.4 正文栏

展示标题、Feed、作者、发布时间、清洗后的正文、已读切换和“在浏览器中打开”。正文和摘要均为空时展示“此订阅未提供正文”，不自动打开网页或书签预览抽屉。

## 10. 删除与持久化

- 删除 Feed 前弹确认框，显示 Feed 名称和即将删除的文章数量。
- 确认后物理删除 Feed，并通过外键级联删除文章。
- 不提供撤销，文章默认永久保留，直到所属 Feed 被删除。
- 应用重启后 Feed、文章、自定义标题、刷新状态和已读状态均保持不变。

## 11. 数据模型

### 11.1 `rss_feeds`

| 字段 | 语义 |
| --- | --- |
| `id` | 本地整数主键 |
| `source_url` | 用户首次输入并规范化后的 URL |
| `feed_url` | 当前实际刷新 URL |
| `site_url` | Feed 对应站点 URL，可空 |
| `title` | Feed 原始标题 |
| `custom_title` | 本地显示名称，可空 |
| `last_successful_fetched_at` | 最后成功刷新时间，可空 |
| `last_failed_at` | 最近失败时间，可空 |
| `last_error` | 最近稳定错误摘要，可空 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

### 11.2 `rss_entries`

| 字段 | 语义 |
| --- | --- |
| `id` | 本地整数主键 |
| `feed_id` | 所属 Feed，删除时级联 |
| `dedupe_key` | 稳定去重键 |
| `guid` | Feed GUID，可空 |
| `title` | 标题 |
| `link` | 原文链接，可空 |
| `author` | 作者，可空 |
| `content_html` | 已清洗正文 |
| `summary` | Feed 或正文派生摘要 |
| `published_at` | 原始发布时间，可空 |
| `fetched_at` | 抓取时间 |
| `is_read` | 本地已读状态 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

最小约束与索引：

- `UNIQUE rss_feeds(feed_url)`；
- `UNIQUE rss_entries(feed_id, dedupe_key)`；
- `INDEX rss_entries(feed_id, COALESCE(published_at, fetched_at) DESC, id DESC)`；
- `INDEX rss_entries(is_read, COALESCE(published_at, fetched_at) DESC, id DESC)`。

## 12. 系统边界

后端模块：

```text
rss/
  model.rs
  parser.rs
  fetcher.rs
  sanitizer.rs
  repository.rs
  service.rs
  commands.rs
```

- React Query 管理列表、详情、计数和 mutation 缓存，不增加全局状态库。
- RSS 只暴露 Tauri commands，不进入 Axum HTTP API 和 Chrome 扩展。
- command 保持薄适配，业务用例由 service 组织，SQL 只存在于 repository/migration。

## 13. 两个参考项目的复用审计

### 13.1 许可证边界

- Folo 根项目为 AGPL-3.0，并对部分图标另有约束：只参考数据流、处理顺序和 UI 模式，不复制源码、样式或资源。
- Rss_Reader_Tauri 的 `package.json` 与 README 声明 ISC，但仓库快照没有独立 LICENSE 文件：可以参考其短小处理形式；若后续需要逐行复制，应先补做上游许可证核验和归属记录。当前计划不逐行复制。

### 13.2 可直接采用的依赖与标准能力

| 来源 | 采用内容 | 决策 |
| --- | --- | --- |
| Rust 生态 | `feed-rs` 的统一 parser 和 model | 直接采用依赖和 API，不分别维护 RSS/Atom parser |
| Rss_Reader_Tauri | `scraper` 的 HTML selector 形式 | 用于网页 `link[rel=alternate]` 发现，不复制其 HTML 字符串重建算法 |
| 两项目 | `url::Url::join`/`new URL` 处理相对地址 | Rust 统一使用现有 `url` crate，不写路径拼接规则 |
| Folo | DOMPurify allowlist 清洗形式 | Rust 改用成熟 sanitizer crate；不复制 AGPL TypeScript 实现 |
| Folo | 清洗后再渲染、运行时修正相对媒体 URL | 采用处理顺序，实际实现落在 Rust 入库边界 |

### 13.3 可参考但必须改造的处理形式

| 参考点 | 可借鉴内容 | 必须改造的原因 |
| --- | --- | --- |
| `RssParser::parse` | 不同 Feed 格式统一映射 Entry | 具体解析改由 `feed-rs` 完成，业务层只做领域映射与边界校验 |
| `rss_item_to_article` | `content:encoded → description`、RFC2822/Dublin Core 日期兜底 | 不用当前时间伪装原发布时间；补 GUID、摘要、清洗和稳定去重键 |
| `atom_item_to_article` | `content → summary`、`alternate` 链接、作者转换 | 补缺失链接、相对 URL、HTML 清洗和 nullable 发布时间 |
| `fix_image_url` | 使用基地址修正 `//`、根路径和相对路径 | 统一交给 `Url::join` 和 sanitizer 属性处理，不使用手写 HTML 替换 |
| Folo Entry store | 远程字段更新时保留本地正文/状态的分离思想 | 本应用只有本地 SQLite，使用单事务 upsert 即可，不引入镜像 store |
| Folo 三栏阅读器 | Feed/文章/正文的职责边界和空正文降级 | 复用当前应用组件与主题，不复制 Folo UI 代码 |

### 13.4 明确不复用

- Rss_Reader_Tauri 的 Headless Chrome 403 回退、字符串方式 HTML 重写、只按链接去重、先插 Feed 再异步验证、直接 `innerHTML` 渲染、自动重试和大文件 command 编排。
- Folo 的云端 API/store 同步、RSSHub、Readability、AI、多媒体布局、公开列表以及任何 AGPL 源码或图标。

### 13.5 当前 app 应优先复用的现有能力

| 当前能力 | 复用方式 |
| --- | --- |
| `preview/security.rs` 的 HTTP scheme、DNS 与公共 IP 校验 | 抽取为通用安全网络模块，书签预览与 RSS 共用底层结果类型 |
| `preview/web.rs` 的禁用自动重定向、逐跳解析校验和 host 地址绑定 | 抽取通用受限 HTTP 客户端；RSS 增加响应类型与 5 MB 流式限制 |
| 数据库 migration runner | 新增连续 schema 版本，不另建迁移系统 |
| 书签查询的版本化 Base64 URL-safe 游标 | 提取通用 encode/decode helper，RSS 使用自己的强类型 cursor payload |
| `AppError`/`AppResult`、repository/service/command 分层 | RSS 完全沿用 |
| `CollapsibleSidebar`、Dialog、AlertDialog、Toast、Empty | RSS 页面直接复用 |
| React Query query key、mutation 和事件失效模式 | RSS 使用独立 query key namespace，不增加状态库 |

## 14. 非目标

- Feed 分组、OPML、全文搜索、文章收藏和一键收藏到书签；
- Readability、原网页正文抓取、书签预览抽屉复用；
- AI 摘要/翻译、后台定时调度、桌面通知、自动重试；
- RSSHub、JSON Feed、私有 Feed、图片代理/缓存；
- 本地 HTTP API、Chrome 扩展、RSS 页面内部快捷键、可调栏宽和批量已读。

## 15. 验收标准

1. 直接 RSS、Atom 和带标准声明的普通网页均能完成订阅；多 Feed 网页可在单弹窗内选择和预览。
2. 无效、重复、超时、过大、重定向过多和非公共目标返回稳定错误，失败不留下数据。
3. 刷新能够新增文章、更新远程字段并保留已读状态；15 分钟和并发 4 的规则正确。
4. 全部、未读和单 Feed 查询以及 30 条游标分页无重复、无遗漏。
5. 点击文章正确更新已读状态和计数；未读视图在当前缓存中不跳动。
6. 数据库中的正文已经过清洗，危险标签、属性和协议不能执行。
7. 删除确认展示文章数量，确认后 Feed 与文章级联删除。
8. 应用重启后全部 RSS 数据与状态保持不变。
9. RSS 不改变现有书签预览、HTTP API、Chrome 扩展、笔记和 Todo 行为。
