# 书签网页预览 Sheet 需求规格

## 1. 背景与目标

当前书签标题点击后会通过系统浏览器打开 URL，并记录一次访问。用户希望在不离开桌面应用的情况下快速浏览书签内容，同时保留标题外部打开的现有行为。

本期目标是在书签页增加一个从右侧打开的阻断式网页预览 Sheet：点击书签卡片的非操作区域后，用 iframe 加载书签地址；关闭 Sheet 后恢复书签列表操作。

本期采用 iframe 作为 MVP，并将网页渲染封装成独立组件，以便实际使用证明 iframe 兼容率不足后再评估替换为 Tauri 子 WebView。

## 2. 术语与方案定位

本功能属于应用内网页预览（live web preview），不是常见笔记软件中仅展示标题、摘要、封面和域名的元数据 link preview。

采用 iframe 意味着：

- 允许嵌入的网站可以直接在应用内浏览；
- 目标网站可以通过 `X-Frame-Options` 或 CSP `frame-ancestors` 拒绝嵌入；
- 应用不绕过目标网站的安全策略，失败时通过顶部栏提供系统浏览器出口；
- 是否升级到 Tauri 子 WebView，由用户在实际使用一段时间后主观决定，不设置自动统计或固定阈值。

## 3. 用户交互

### 3.1 书签卡片点击区域

- 点击书签标题：保持现有行为，通过系统浏览器打开 URL，并记录一次访问。
- 点击星标、编辑、删除等操作控件：只执行控件自身行为，不打开预览。
- 点击 URL、描述、访问次数或卡片留白：打开网页预览 Sheet，并记录一次访问。
- 标题和所有独立操作控件必须阻止点击事件冒泡，避免同时打开预览。
- 打开预览后的 iframe 刷新和内部导航不重复记录访问。
- 从预览顶部栏再次选择“在浏览器中打开”不重复记录访问，因为打开 Sheet 时已经记录。

### 3.2 Sheet 布局

- 使用 shadcn Sheet，从右侧滑入。
- Sheet 左边缘始终对齐书签主内容区，动态占满其余宽度。
- Sheet 覆盖顶部搜索区和书签卡片区。
- 左侧固定 224px 的书签标签栏和应用顶部导航保持可见。
- Sheet 外区域由遮罩阻断；打开期间不能操作标签栏、导航或其他书签。
- 点击遮罩不关闭 Sheet。
- 顶部关闭按钮和 `Esc` 可以关闭 Sheet。
- 打开后焦点落在关闭按钮；关闭后焦点恢复到触发预览的书签卡片。
- 关闭时销毁 iframe；再次打开同一书签时从原始 URL 重新加载，不缓存页面状态。

### 3.3 顶部栏

顶部栏包含：

- 书签标题；
- 原始 URL 的域名；
- “在浏览器中打开”按钮；
- 刷新按钮；
- 关闭按钮。

标题和域名始终代表原始书签。首版不读取或同步 iframe 内当前页面的 URL，也不提供前进、后退或地址栏。

### 3.4 iframe 导航

- iframe 内普通同框链接可以继续导航。
- 禁止通过 `target="_blank"` 或 `window.open` 创建弹窗或新窗口。
- 需要离开当前预览时，用户使用顶部栏的“在浏览器中打开”。

## 4. URL 路由与失败兜底

### 4.1 HTTP(S) URL

- `http://` 和 `https://` URL 进入 iframe 预览。
- 打开 Sheet 后立即记录一次访问。
- iframe 被安全策略拒绝时，接受系统 WebView 自带错误页表现；顶部栏始终提供外部打开。
- 首版不代理、抓取或改写目标网页响应，也不自动判断拒绝嵌入。

### 4.2 其他协议

- `file:`、`javascript:` 和其他非 HTTP(S) 协议不得进入 iframe。
- 在创建 Sheet 前校验协议，并直接尝试交给系统处理。
- 系统打开调用未抛错后记录一次访问。
- 系统无法处理或调用抛错时：
  - 不创建 Sheet；
  - 不留下遮罩、空白页或阻断状态；
  - 保持书签列表可操作；
  - 使用现有 toast 体系显示明确的失败提示；
  - 不记录访问。

Tauri shell API 若无法确认目标应用最终是否成功启动，以调用是否抛错作为本期成功边界。

## 5. iframe 安全策略

iframe 使用以下 sandbox：

```text
allow-scripts allow-forms allow-same-origin
```

约束如下：

- 不开放弹窗、新窗口和下载；
- 不开放摄像头、麦克风、定位等设备能力；
- 不读取、注入或修改跨域网页内容；
- 不承诺第三方 Cookie、既有登录状态或登录流程可用；
- 不为提高兼容率移除 sandbox。

## 6. Loading 状态

- iframe 创建后立即展示 loading。
- 收到 iframe `load` 事件后隐藏 loading。
- 不设置加载超时，不根据超时推断失败。
- iframe 的 `error` 事件对跨域和安全策略拒绝不可靠，本期不实现自动失败识别。
- loading 必须实现为独立、可替换的状态区域。
- 大面积 loading 后续计划采用更精致的插画或动画，但视觉方案尚未确定；本期不新增插画资产、动画依赖或未经确认的视觉设计。

## 7. 组件与状态边界

- `BookmarkView` 持有当前预览书签状态，确保 Sheet 能覆盖搜索区和主内容区。
- `ResultList` / `BookmarkRow` 只报告预览意图，不持有 Sheet 生命周期。
- 新增独立网页预览组件，负责 Sheet 顶部栏、iframe、loading、刷新和关闭交互。
- iframe 刷新通过更新局部 key 或等价的重新加载方式实现，不影响访问计数。
- 预览组件的输入以 `Bookmark | null` 和开关/关闭回调为主，不提前设计原生 WebView 专用抽象。
- 未来替换 WebView 时允许修改预览组件内部和 Tauri 权限配置，但卡片点击契约与 `BookmarkView` 的选中状态应尽量保持稳定。

## 8. 自动化测试

至少覆盖：

1. 点击卡片非操作区域打开 Sheet。
2. 点击标题仍调用系统浏览器，且不打开 Sheet。
3. 点击星标和其他操作控件不打开 Sheet。
4. 打开 HTTP(S) 预览记录一次访问。
5. iframe 内刷新与顶部外部打开不重复记录访问。
6. HTTP(S) URL 正确传给 iframe。
7. 非 HTTP(S) URL 不创建 Sheet，并调用系统打开。
8. 非 HTTP(S) 系统打开失败时显示 toast、保持页面可操作且不记录访问。
9. 打开时展示 loading，iframe `load` 后隐藏。
10. 刷新重新加载 iframe。
11. 关闭按钮和 `Esc` 可以关闭，点击遮罩不能关闭。
12. 关闭时卸载 iframe，并将焦点恢复到触发卡片。
13. iframe sandbox 与权限约束符合本规格。

## 9. 手工验证

在真实 Tauri 应用中至少验证：

- 一个允许 iframe 嵌入的网站；
- 一个通过响应头拒绝 iframe 的网站；
- 一个 `http://` 地址；
- 一个非 HTTP(S) 自定义协议；
- Sheet 打开、关闭、窗口缩放、iframe 内导航和外部打开的实际体验。

实际使用一段时间后，由用户主观判断 iframe 可用率是否足够；若不足，再单独设计 Tauri 子 WebView 版本。

## 10. 非目标

- Tauri 子 WebView。
- Open Graph 元数据抓取、link preview 卡片、Iframely 或 oEmbed。
- iframe 失败率埋点或自动成功率统计。
- 自动识别网站拒绝嵌入。
- 代理或改写目标网页响应。
- 前进、后退、地址栏和 iframe 当前 URL 同步。
- 多标签页和预览缓存。
- 登录态可用性承诺。
- 弹窗、下载和设备权限。
- loading 插画与最终动画视觉设计。

## 11. 验收标准

1. 原有标题外部打开、星标和卡片菜单行为无回归。
2. 点击卡片内容区能稳定打开阻断式网页预览 Sheet。
3. Sheet 的覆盖范围、关闭方式、焦点恢复符合交互规格。
4. iframe 的打开、loading、刷新、销毁、安全权限和访问计数符合本规格。
5. 非 HTTP(S) 地址和系统打开失败不会把用户困在不可操作状态。
6. 相关前端自动化测试、TypeScript 检查和桌面端构建通过。
7. 完成代表性网址的 Tauri 真机手工验证，并记录 iframe 兼容性观察。
