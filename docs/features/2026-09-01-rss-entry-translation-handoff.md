## 2. 当前代码事实

- `apps/desktop/src/rss/RssEntryReader.tsx` 已有翻译图标按钮，但没有点击行为。
- `apps/desktop/src-tauri/src/translation.rs` 已实现小牛翻译 provider，固定 `auto -> zh`，单请求最多 5000 个 Unicode 字符。
- 翻译目前只通过本地 HTTP `POST /api/translations` 暴露，尚未接入 RSS Tauri command。
- `rss_entries` 目前没有译文、原文指纹或翻译状态字段，也没有独立译文表。
- RSS 刷新会更新已有条目的远程正文，因此译文必须基于原文指纹判定是否有效。
- 项目没有适用于该功能的持久后台任务队列；应用关闭后无需继续翻译。
- 本次需求确认阶段没有修改任何产品代码或数据库。

## 3. 已确认需求

### 3.1 功能范围

- 功能仅供个人使用，目标语言固定为中文。
- 第一版只复用现有小牛翻译，不增加供应商选择或用户语言配置。
- 用户点击当前 RSS 条目的翻译按钮后，优先翻译 `content_html`；正文不存在时翻译 `summary`。
- 正文和摘要都不存在时禁用按钮，并提供“暂无可翻译内容”提示。
- 只翻译正文或摘要，不翻译标题，不抓取原网页全文。
- 中文原文不做本地预检，仍交给 provider；结果照常保存。

### 3.2 HTML 与分段

- 保留原 HTML 的段落、标题、列表、引用、链接和图片，只替换可见文本。
- 翻译模式与无图模式相互独立，可以同时启用。
- 超过 provider 上限的内容优先按块级段落拆分；单个超长文本节点继续按安全字符边界拆分。
- 任何发往 provider 的单次请求都不得超过 5000 个 Unicode 字符。
- 所有分段成功后才重建并保存完整译文；任一分段失败都不保存半成品。

### 3.3 持久化与失效

- 每个 RSS 条目只保留一个当前译文，不维护翻译历史或多版本。
- 译文至少关联条目 ID、来源类型（正文/摘要）、原文指纹、完整译文 HTML、provider、源语言和翻译时间。
- 原文指纹不变时直接返回数据库译文，不再次调用 provider；应用重启后仍可复用。
- RSS 刷新导致原文变化时，旧译文立即视为无效，用户下次点击时重新翻译。
- 翻译期间原文发生变化时，保存前的二次指纹校验必须拒绝旧结果，并提示用户内容已更新。
- 删除 RSS 条目时，通过外键级联删除译文。

### 3.4 交互与并发

- 新进入或重新打开条目时默认显示原文，即使数据库已有有效译文。
- 点击翻译按钮后显示 loading，期间按钮不可重复点击；成功后立即显示译文并进入选中样式。
- 再次点击已选中的翻译按钮切回原文并取消选中。
- 切换到其他条目不会取消翻译；完成后仍保存。返回该条目时恢复同一任务的 loading 状态。
- 同一条目同一时间最多一个翻译任务；不同条目可独立翻译。
- 翻译未配置或失败时保持原文、清除 loading/选中状态、显示可理解的错误，并允许重试。
- 错误信息和日志不得暴露 API 密钥或敏感 provider 响应。

## 4. 推荐技术边界

- 后端负责来源选择、指纹、缓存判定、HTML 文本提取/重建、分段、provider 调用、原子保存和任务去重。
- 前端只按 entry ID 发起翻译、保存条目级进行中状态并切换原文/译文。
- 新增 RSS 专用 Tauri command，不让前端依赖本地 HTTP server 的端口和生命周期。
- 建议新增独立 `rss_entry_translations` 表，而不是持续扩展 `rss_entries`；以 entry ID 做唯一键和级联外键。
- command 的单次调用顺序：读取当前原文 → 计算指纹 → 查询有效缓存 → 翻译 → 重新读取并核对指纹 → 事务写入 → 返回。

## 5. 实施任务与测试粒度

### T1：数据契约与迁移

- 新增连续 schema migration、译文模型和 Repository 方法。
- 仓储集成测试：新库建表、旧库升级、唯一约束、增查覆盖、级联删除、迁移回滚。

### T2：内容处理管线

- 实现正文/摘要选择、HTML 可见文本提取、5000 字分段和原结构重建。
- 纯函数单测：嵌套标签、链接、图片、实体字符、空白、纯文本摘要，以及 4999/5000/5001 字边界。
- 验证链接、图片和非文本属性不会被翻译或破坏。

### T3：后端翻译用例

- 实现缓存命中、原子保存、指纹失效、保存前二次校验和条目级任务去重。
- 使用 fake provider 测试：首次成功、缓存零调用、任一分段失败零写入、原文变化、并发同条目单调用、不同条目独立执行。

### T4：Tauri 契约

- 注册 RSS 翻译 command 和稳定返回/错误结构。
- 契约测试覆盖参数映射、序列化、无内容、未配置、provider 失败、内容已更新及敏感信息脱敏。

### T5：前端数据层

- 增加 RSS 翻译 API 和以 entry ID 为键的进行中任务状态。
- 测试切换条目不取消任务、返回时恢复 loading、重复操作不重复 invoke、有效缓存立即展示。

### T6：阅读器交互

- 接通翻译按钮的 loading、selected、disabled、原文/译文切换和错误提示。
- 组件测试覆盖无内容、成功切换、再次点击恢复、已有译文默认原文、切走返回、无图模式组合和失败重试。

### T7：回归验收

- 运行 Rust 与前端完整测试、静态检查和构建。
- 验证现有 RSS 刷新、阅读、无图模式、小牛配置及其他应用功能无回退。

任务依赖顺序：`T1 → T2 → T3 → T4 → T5 → T6 → T7`。每项测试随任务完成，不集中到最后补写。

## 6. 最终验收标准

1. 首次点击可翻译正文或摘要、持久化并立即展示。
2. 同一原文后续点击零 provider 调用，重启应用后仍能复用。
3. 任意单次 provider 请求不超过 5000 字，长正文可完整翻译并保留 HTML 结构。
4. 任一分段失败时数据库不存在半篇译文。
5. 原文更新后不会展示、复用或保存旧正文对应的译文。
6. 同一条目不会并发重复翻译，切换条目不会丢失进行中状态。
7. loading、选中、禁用、错误和无图组合状态符合已确认交互。
8. 错误可恢复且不泄露敏感信息。
9. 所有新增测试、现有测试、静态检查和构建通过。
