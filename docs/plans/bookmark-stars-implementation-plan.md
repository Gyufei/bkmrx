# 书签星标功能实施计划

本计划采用测试驱动：每一阶段先写能够失败的行为测试，确认失败原因与目标一致，再写最小实现使其通过，最后运行相关回归测试。

## 1. 数据库与领域模型

- 先测试新数据库 schema v2 以及 v1 到 v2 的迁移。
- 先测试书签读取包含 `starred_at`。
- 先测试设置和取消星标的持久化、时间更新、not-found 行为。
- 实现 v2 schema、迁移、模型字段和仓储方法。

验证：`database_repository` 集成测试通过。

## 2. 默认星标查询

- 先测试空搜索且无标签仅返回星标，并按 `starred_at DESC, id DESC` 分页。
- 保留并回归测试空搜索加标签、文本搜索和游标绑定行为。
- 实现星标查询模式及对应游标，不改动现有标签和文本查询分支。

验证：`search_pagination` 集成测试通过。

## 3. 服务与桌面命令

- 先测试星标变更只在成功时发送通知。
- 实现服务方法、Tauri command、invoke 封装和查询缓存失效链路。

验证：服务测试和 TypeScript API 测试通过。

## 4. 导入导出兼容

- 先测试导出包含星标时间并可往返导入。
- 先测试旧记录字段缺失时：新建为未星标，合并时保留本地状态。
- 先测试新版记录按 `updated_at` 覆盖星标，以及非法时间被拒绝。
- 实现可区分“字段缺失”和“明确 null”的传输模型与合并逻辑。

验证：`transfer` 集成测试通过。

## 5. 前端交互

- 先测试空查询模式向列表传入星标上下文和专用空状态。
- 先测试星形按钮的可访问名称、点击隔离和星标 API 调用。
- 先测试默认星标列表取消前确认并在成功后消失。
- 先测试搜索或标签结果取消时不确认且不移除当前卡片。
- 实现最小 UI 和 mutation，不改变卡片其他操作。

验证：`BookmarkView`、`ResultList`、API 测试通过。

## 6. 回归与质量审查

- 运行 Rust 全量测试、前端全量测试和生产构建。
- 检查 git diff 与知识图谱影响范围，确保每处修改都可追溯到规格。
- 对正确性、兼容性、交互、可访问性和测试覆盖进行最终代码审查。

验证：所有检查通过，且无未解释的回归或范围外改动。
